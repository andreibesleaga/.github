# Contributing

This guide applies to every repository under [andreibesleaga](https://github.com/andreibesleaga)
that does not have its own `CONTRIBUTING.md`. A repository's own guide, README or `AGENTS.md`
takes precedence where they differ.

## Before you start

- **Bug or idea:** open an issue in the repository first and describe what you found or want.
  For anything larger than a small fix, wait for a reply before writing code.
- **Security problem:** do not open a public issue with exploit details. Follow
  [SECURITY.md](https://github.com/andreibesleaga/.github/blob/main/SECURITY.md) or the repository's own security policy.
- **Question:** see [SUPPORT.md](https://github.com/andreibesleaga/.github/blob/main/SUPPORT.md).

## Pull requests

1. Fork the repository and branch from its default branch, unless its README names another
   base branch.
2. Keep one change per pull request, and keep it small enough to review in one sitting.
3. Run the repository's tests and linters as its README describes, and add or update tests for
   the behaviour you change.
4. Update the documentation and the changelog (if the repository has one) in the same pull
   request.
5. Describe what changed and why, and link the issue.

Do not commit secrets, API keys, `.env` files or personal data.

## Licence of contributions

By contributing, you agree that your contribution is licensed under the licence of the repository
you contribute to (see its `LICENSE` file).

## Conduct

All participation follows the [code of conduct](https://github.com/andreibesleaga/.github/blob/main/CODE_OF_CONDUCT.md).

These are personal open-source projects maintained by one person. Reviews are best-effort, with no
guaranteed response time.
